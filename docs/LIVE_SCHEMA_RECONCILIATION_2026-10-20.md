1. Keep the live project read-only.
2. Build a migration-by-migration reconciliation table: objects created/altered, expected grants/RLS/policies/functions, live presence, live definition, and whether the change is already present in substance.
3. Read back the exact definitions of relevant policies, triggers, functions, grants, enums, and constraints before deciding an operation is missing. Table names alone are insufficient.

### Minimum evidence bundle for every touched object

- **Migration history:** complete ordered ledger rows (version, name, statements/checksum if available, application time and actor if exposed), plus project reference and engine version. A ledger row alone does not prove the matching DDL remains present.
- **Tables and columns:** schema/name/relkind; column order, type/enum, nullability, default, identity/generated status, collation and comments for each affected table.
- **Indexes and constraints:** exact index definitions, uniqueness, predicates, validity/readiness, PK/FK/check/exclusion constraint definitions and validation/deferrability state.
- **RLS and policies:** RLS and FORCE RLS flags plus every `pg_policies` expression (command, roles, USING, WITH CHECK) for each affected table, not merely policy names.
- **Grants:** table/sequence/column/function ACLs and ownership; `PUBLIC`, `anon`, `authenticated`, `service_role`, and other roles; default privileges by schema **and grantor/owner**.
- **Functions:** exact identity/signature, body, language, owner, SECURITY DEFINER/INVOKER, volatility, `search_path`/`proconfig`, return type, ACL and dependency/caller inventory for every affected function.
- **Triggers:** exact trigger definition, function identity, enabled state, timing/events, row/statement scope, deferrability and constraint linkage.
- **Data assumptions:** read-only aggregate counts only for duplicate keys, invalid links, rows violating new checks, over-cap agencies, missing/ambiguous consent, duplicate state/event IDs, and any rows that make unique indexes/backfills fail. No personal data is needed in the report.
- **Storage where relevant:** bucket metadata and object policies for migration 0002, including existing path conventions and object counts; do not infer storage policy state from `public` schema metadata.
